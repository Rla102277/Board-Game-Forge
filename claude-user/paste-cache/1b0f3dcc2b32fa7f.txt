## EXECUTIVE SUMMARY

### Current Collaboration System (✅ Exists, ❌ Weak)

```
Share Dialog
├─ Invite by email (inviteRole: admin/editor/commenter/viewer)
├─ Public link toggle
├─ Member list with role dropdowns
└─ Activity feed (who did what)

Comments System
├─ Comment on projects, rules, assets
├─ @mentions
└─ Reply threads

Presence
├─ Cursor indicators (see where others are)
├─ Editing indicators (who's editing what)
└─ Activity feed (shows recent changes)

Notifications
├─ @mentions
├─ Assignments
└─ Status changes
```

### Problems

**Designer Issues:**
- ❌ Can't see who's working on what right now (no active presence dashboard)
- ❌ Comments are scattered (no unified inbox)
- ❌ No way to request feedback from specific people
- ❌ No version control (undo/rollback)
- ❌ Conflicts when 2 people edit same card simultaneously

**CTO Issues:**
- ❌ No audit trail (who changed what, when, why)
- ❌ No fine-grained permissions (card-level, rule-level)
- ❌ Roles are too coarse (4 roles, can't customize)
- ❌ No workspace management (1 project per account)
- ❌ No team/org structure
- ❌ No session management (can't see who's logged in)
- ❌ No conflict resolution (last-write-wins)
- ❌ No data export/backup
- ❌ No IP allowlisting or SSO (enterprise features missing)

#### 3. 🔄 REAL-TIME CONFLICT RESOLUTION

**Scenario: 2 designers edit same card simultaneously**

```
Current (Broken):
Randy edits Spell Bolt: Cost 3 → 2
Sarah edits Spell Bolt: Power 5 → 6
Result: Last write wins (Sarah's changes, Randy's lost)
😡 Randy: "Where did my cost change go?"

New (Fixed):
CONFLICT DETECTED:
┌─────────────────────────────────────┐
│ ⚠️  CONFLICT: Spell Bolt            │
│                                     │
│ You edited: Cost 3 → 2              │
│ Sarah edited: Power 5 → 6           │
│                                     │
│ RESOLUTION OPTIONS:                 │
│ ├─ ✅ [Merge] (apply both changes)  │
│ │   Result: Cost 2, Power 6         │
│ ├─ 🔄 [Request Sarah's Intent]      │
│ │   Message: "Are these compatible?"│
│ ├─ ↩️ [Revert Your Changes]          │
│ └─ 🔄 [Negotiate] (chat with Sarah) │
│                                     │
│ Sarah (currently editing): Online   │
│ [Propose Merge] [Chat] [Resolve]    │
└─────────────────────────────────────┘
```

**What happens:**
- ✅ Users are notified of conflicts in real-time
- ✅ Can see what the other person changed
- ✅ Choose: merge, revert, or negotiate
- ✅ Automatic chat channel opens
- ✅ Change is blocked until resolved
- ✅ Version is saved (can rollback later)

## IMPLEMENTATION ARCHITECTURE

### 1. DATABASE SCHEMA ADDITIONS

```sql
-- Workspace Management
CREATE TABLE workspaces (
  id INT PRIMARY KEY,
  name VARCHAR(255),
  owner_id INT,
  created_at TIMESTAMP,
  plan VARCHAR(50), -- free, team, enterprise
  max_members INT,
  features JSONB  -- sso, ip_allowlist, audit_export, etc.
);

-- Fine-Grained Roles
CREATE TABLE roles (
  id INT PRIMARY KEY,
  workspace_id INT,
  name VARCHAR(100),
  description TEXT,
  permissions JSONB,  -- {view: [...], edit: [...], delete: [...]}
  custom BOOLEAN,     -- true if user-created, false if built-in
  created_by INT,
  created_at TIMESTAMP
);

-- Member Management
CREATE TABLE workspace_members (
  id INT PRIMARY KEY,
  workspace_id INT,
  user_id INT,
  role_id INT,
  status VARCHAR(50), -- active, suspended, invited
  invite_token VARCHAR(255),
  invited_by INT,
  invited_at TIMESTAMP,
  accepted_at TIMESTAMP,
  last_active_at TIMESTAMP
);

-- Audit Logging
CREATE TABLE audit_log (
  id INT PRIMARY KEY,
  workspace_id INT,
  user_id INT,
  action VARCHAR(50),  -- create, update, delete, share, view
  entity_type VARCHAR(50),  -- card, rule, project, user, etc.
  entity_id INT,
  changes JSONB,  -- before/after values
  ip_address VARCHAR(45),
  user_agent TEXT,
  created_at TIMESTAMP,
  INDEX (workspace_id, created_at),
  INDEX (user_id, created_at)
);

-- Conflict Resolution
CREATE TABLE edit_conflicts (
  id INT PRIMARY KEY,
  workspace_id INT,
  project_id INT,
  entity_type VARCHAR(50),
  entity_id INT,
  user_a_id INT,
  user_b_id INT,
  user_a_change JSONB,
  user_b_change JSONB,
  status VARCHAR(50),  -- pending, merged, reverted, negotiated
  resolution JSONB,
  created_at TIMESTAMP,
  resolved_at TIMESTAMP
);

-- Session Management
CREATE TABLE sessions (
  id INT PRIMARY KEY,
  user_id INT,
  workspace_id INT,
  token VARCHAR(255),
  ip_address VARCHAR(45),
  user_agent TEXT,
  created_at TIMESTAMP,
  last_active_at TIMESTAMP,
  expires_at TIMESTAMP,
  INDEX (user_id, workspace_id)
);

-- Feedback & Approvals
CREATE TABLE feedback_items (
  id INT PRIMARY KEY,
  workspace_id INT,
  project_id INT,
  type VARCHAR(50),  -- comment, request, approval
  entity_type VARCHAR(50),
  entity_id INT,
  requester_id INT,
  approver_id INT,
  content TEXT,
  status VARCHAR(50),  -- pending, approved, rejected, discussed
  created_at TIMESTAMP,
  resolved_at TIMESTAMP
);
```
